# EntrySignalAnalyzer --- 타점 및 Phase 로직 개선 제안

> 대상: `EntrySignalAnalyzer.java`\
> 검토 범위: **경제/트레이딩 관점의 타점(Entry) 및 Phase 판정 로직**\
> 제외: 코드 가독성, 클래스 구조, 아키텍처, 리팩터링 품질
>
> 목적: 현재 구현을 최대한 유지하면서 **시장 국면 판단 → 시장 구조 →
> 가격 위치 → 진입 트리거 → 진입가 → 손절/목표가**가 경제적으로
> 자연스럽게 연결되도록 개선한다.

------------------------------------------------------------------------

## 1. 가장 먼저 고쳐야 할 문제 --- 캔들 몸통/꼬리 계산

현재 로직에서 다음과 같은 계산이 사용된다.

``` java
double bodyTop = Math.max(currentPrice, yesterdayPrice);
double bodyBottom = Math.min(currentPrice, yesterdayPrice);
```

이 방식은 실제 캔들의 `시가(Open) ↔ 종가(Close)`를 몸통으로 계산하는
것이 아니다.

결과적으로:

-   전일 종가
-   현재 종가

사이의 변화를 캔들 몸통처럼 취급하게 된다.

따라서 `upperWickRatio`, `lowerWickRatio`가 실제 캔들 꼬리 비율과 달라질
수 있고, 다음과 같은 판정까지 영향을 받을 수 있다.

-   `bullTrap`
-   `bearTrap`
-   `panicSelling`
-   `isConfirmedFakeOut`
-   `isConfirmedCapitulation`

### 권장 계산

``` java
double bodyTop = Math.max(open, close);
double bodyBottom = Math.min(open, close);

double upperWick = high - bodyTop;
double lowerWick = bodyBottom - low;

double candleRange = high - low;
```

**우선순위: 최상**

이 부분은 다른 로직을 손보기 전에 먼저 수정하는 것이 좋다.

------------------------------------------------------------------------

# 2. 현재 타점 계산의 핵심 문제

현재 `calculateTargets()` 계열 로직은 상당 부분을 ATR 기반 가격 계산으로
처리한다.

예를 들어:

``` java
double bestSupport =
        !downSupports.isEmpty()
        ? downSupports.get(0)
        : cur - (atr * 0.5);

primaryEntry =
        Math.max(bestSupport, cur - (atr * ENTRY_SETUP_MAX_ATR));
```

ATR 자체는 매우 유용하다.

하지만 **ATR은 진입 가격을 결정하는 핵심 근거라기보다 변동성의 크기와
리스크 버퍼를 결정하는 도구**로 사용하는 편이 자연스럽다.

즉,

> 현재가 - 0.5 ATR = 진입가

가 아니라,

> 시장 구조상 매수세가 다시 들어올 가능성이 높은 가격대가 어디인가?\
> 그 가격대가 현재 변동성(ATR) 안에서 유효한가?

를 먼저 판단해야 한다.

------------------------------------------------------------------------

# 3. 지지선을 단순 나열하지 말고 "지지 구간"으로 봐야 함

현재 지지 후보에는 대략 다음과 같은 것들이 사용된다.

-   Pivot S1/S2/S3
-   Bollinger Lower
-   MA20
-   MA50
-   POC
-   VWAP20
-   기타 최근 저점

문제는 이 레벨들이 사실상 비슷한 가중치로 취급되고, 가까운 지지 하나를
선택하는 방식이 된다는 점이다.

예를 들어:

``` text
MA20   = 95.2
VWAP   = 95.0
POC    = 94.9
최근저점 = 94.8
```

이것은 서로 완전히 독립된 네 개의 지지가 아니라,

> 94.8 \~ 95.2 부근에 매물/수급/추세 기준이 겹치는 하나의 강한 지지 구간

으로 보는 것이 더 적절하다.

### 권장 개념

ATR을 이용해 가까운 가격들을 클러스터링한다.

예:

``` text
94.8 ───────── 95.2
       SUPPORT ZONE
```

그리고:

-   Zone Low
-   Zone Mid
-   Zone High
-   Zone Strength

를 계산한다.

진입은 이 Zone을 중심으로 결정한다.

------------------------------------------------------------------------

# 4. 타점 계산의 기본 구조를 바꿀 필요가 있음

현재 구조는 대략:

``` text
Phase
 ↓
ATR
 ↓
Entry Price
```

에 가깝다.

보다 자연스러운 구조는:

``` text
Market Regime
      ↓
Market Structure
      ↓
Price Location
      ↓
Entry Trigger
      ↓
Entry Zone
      ↓
Stop Loss
      ↓
Risk / Reward
```

이다.

### 핵심

Phase가 `ENTRY_READY`라고 해서 무조건 현재가에서 일정 ATR만큼 아래
가격을 진입가로 잡는 것이 아니라,

**왜 지금 진입해야 하는지에 대한 구조적 근거가 있어야 한다.**

------------------------------------------------------------------------

# 5. 진입 타입을 최소 3가지로 분리

현재 `ENTRY_READY` 하나가 여러 상황을 동시에 처리하고 있다.

이를 경제적으로 보면 최소한 다음 세 가지는 구분하는 것이 좋다.

## 5-1. Pullback Entry

상승 추세에서 조정이 발생한 뒤 지지에서 재상승하는 형태.

``` text
상승
  ↗
   ↗
    ↘ 조정
     ↘
      ───── 지지
            ↗ 재상승
```

조건 예시:

-   상승 추세
-   MA20 또는 VWAP 또는 이전 돌파 가격대 접근
-   조정 중 거래량 감소
-   지지에서 하락 압력 둔화
-   양봉 또는 반전 캔들
-   단기 모멘텀 개선

→ **가장 전형적인 눌림목 타점**

------------------------------------------------------------------------

## 5-2. Breakout Entry

저항을 돌파하는 형태.

``` text
저항 ─────────────────
                  ↗
                ↗
              ↗
```

필요한 조건:

-   명확한 저항
-   종가 기준 돌파
-   거래량 증가
-   돌파폭이 과도하지 않음
-   돌파 직후 과도한 ATR 확장이 아님

즉:

> 돌파했으니 매수

가 아니라,

> **유효한 돌파 + 수급 확인 + 과도한 추격이 아님**

이어야 한다.

------------------------------------------------------------------------

## 5-3. Reclaim Entry

중요한 지지/기준선을 잠시 잃었다가 다시 회복하는 형태.

예:

``` text
MA20 ─────────────────

가격 ↓
     ↓
     ↓
     ↑ 회복
     ↑
```

조건:

-   핵심 레벨 이탈
-   저점 형성
-   다시 핵심 레벨 회복
-   종가 기준 안착
-   거래량/모멘텀 확인

이 형태는 단순 상승보다 의미가 있다.

------------------------------------------------------------------------

# 6. ENTRY_READY 조건은 너무 단순함

현재 ENTRY_READY에는 다음과 비슷한 논리가 들어간다.

``` java
(nearRecentHigh || breakoutPoc || breakoutVwap)
&&
(bullishCandle || reclaimedMa5)
&&
(bullishVolume || volumeSurge || macdImproving)
```

문제는:

> 저항 근처 + 양봉 + 거래량/모멘텀 개선

이면 하나의 진입 상태로 묶인다는 것이다.

하지만 실제로는:

-   돌파 직전
-   돌파 직후
-   돌파 후 과열
-   눌림목
-   재돌파
-   추세 중간

이 전혀 다른 상황이다.

따라서 `ENTRY_READY` 안에서도 최소한 진입 유형을 구분하는 것이 좋다.

예:

``` text
ENTRY_READY
 ├─ PULLBACK
 ├─ BREAKOUT
 └─ RECLAIM
```

------------------------------------------------------------------------

# 7. 최근 고점 돌파는 "돌파 여부"만 보면 안 됨

현재 `breakoutRecentHigh`가 사실상:

``` text
currentPrice > recentHigh
```

형태라면 문제가 있다.

예를 들어:

### A

최근 고점 돌파:

``` text
+0.1 ATR
```

### B

최근 고점 돌파:

``` text
+1.2 ATR
```

둘 다 단순히:

``` java
breakoutRecentHigh = true;
```

가 된다.

하지만 타점 관점에서는 완전히 다르다.

### 권장 지표

``` java
double breakoutDistanceAtr =
        (currentPrice - recentHigh) / atr;
```

대략적인 해석 예:

``` text
0.0 ~ 0.3 ATR
→ 신선한 돌파

0.3 ~ 0.8 ATR
→ 추격 위험 증가

0.8 ATR 이상
→ 신규 진입보다 추격 자제/보유 관점
```

위 수치는 절대적인 시장 법칙이 아니라 초기 튜닝용 휴리스틱이다.

------------------------------------------------------------------------

# 8. STRONG_HOLD와 ENTRY_READY의 관계는 방향이 좋음

현재처럼:

``` java
if (isStrongHold(e)) return STRONG_HOLD;
if (isEntryReady(e)) return ENTRY_READY;
```

형태로 되어 있는 것은 개념적으로 괜찮다.

왜냐하면 이미 상당히 진행된 강한 추세를:

> "새로운 진입 기회"

로 반복해서 판단하는 문제를 줄일 수 있기 때문이다.

다만 `isStrongHold()` 내부의 점수 계산은 개선할 필요가 있다.

------------------------------------------------------------------------

# 9. STRONG_HOLD 점수에서 상관된 지표가 중복 집계될 가능성

예를 들어 다음 지표들은 사실 상당 부분 같은 현상을 표현한다.

-   MA20 상승
-   MA5 \> MA20
-   가격 \> MA20
-   ADX 상승/높음

이들을 단순히:

``` text
+1
+1
+1
+1
```

으로 더하면 "추세"라는 하나의 증거를 여러 번 계산하는 셈이 된다.

거래 시스템에서는 이를 **double counting / correlated signals** 문제로
볼 수 있다.

### 권장

증거를 그룹으로 나누는 방법이 좋다.

예:

``` text
Trend       0 ~ 3
Momentum    0 ~ 3
Volume      0 ~ 2
PriceAction 0 ~ 3
```

그리고 각 그룹의 최대 기여도를 제한한다.

핵심은:

> 지표 개수가 아니라 서로 독립적인 증거의 개수를 늘리는 것

이다.

------------------------------------------------------------------------

# 10. RECOVERY_WATCH는 너무 빨리 발생할 가능성이 있음

현재 Phase 순서에서:

``` java
if (isRecoveryWatch(e))
    return RECOVERY_WATCH;

if (confirmedDowntrend && isDangerZone(e))
    return DANGER_ZONE;
```

같은 순서가 된다면 주의가 필요하다.

하락 추세 중 하루 강한 반등만으로 `RECOVERY_WATCH`가 되어버리면,

실제로는:

``` text
하락 추세
 ↓
강한 하루 반등
 ↓
다시 하락
```

인 상황에서도 회복 국면처럼 보일 수 있다.

------------------------------------------------------------------------

# 11. 회복은 "하루 반등"보다 "구조 변화"를 봐야 함

보다 자연스러운 단계는:

``` text
1. First Rebound
   ↓
2. Recovery Candidate
   ↓
3. Higher Low 확인
   ↓
4. MA20 회복
   ↓
5. Re-entry
```

특히 중요한 것은:

> 저점 → 반등 → 재조정 → 더 높은 저점(Higher Low)

이다.

즉, 회복 Phase를 판단할 때 **시간적 구조**를 추가하는 것이 좋다.

------------------------------------------------------------------------

# 12. CAPITULATION ≠ BOTTOM

현재 `panicSelling`이나 `isConfirmedCapitulation()`이 포착하는 것은
실제로는:

> 투매/패닉/매도 클라이맥스

에 더 가깝다.

그 자체가:

> "바닥이 확인되었다"

는 의미는 아니다.

전형적인 구조:

``` text
급락
 ↓
투매
 ↓
CAPITULATION
 ↓
반등
 ↓
재시험
 ↓
저점 방어
 ↓
HIGHER LOW
 ↓
회복
```

따라서 CAPITULATION 직후 공격적인 진입을 허용하기보다,

**안정화 → 재시험 → 지지 확인**

을 거친 뒤 진입 신뢰도를 높이는 편이 좋다.

현재 CAPITULATION의 `maxWeight = 10`처럼 보수적으로 제한하는 방향은
개념적으로 맞다.

------------------------------------------------------------------------

# 13. "스마트머니 유입"이라는 표현은 주의

가격 상승 + 거래량 증가만으로:

> 스마트머니가 들어왔다

라고 단정할 수는 없다.

가격/거래량 데이터만으로는 참여자의 정체를 직접 확인할 수 없기 때문이다.

따라서 UI 문구나 분석 문구에서는:

### 피해야 할 표현

``` text
스마트머니 유입
기관 매집
큰손 매수
```

### 권장 표현

``` text
거래량 증가와 함께 가격 회복이 나타남
상승 방향의 수급 강도가 강화됨
매수 압력이 이전보다 증가한 것으로 관찰됨
```

즉, 관측 가능한 현상과 참여자에 대한 추론을 분리한다.

------------------------------------------------------------------------

# 14. RSI 70/30을 절대적인 과매수/과매도로 취급하지 않는 것이 좋음

현재:

``` java
overbought = RSI >= 70;
oversold = RSI <= 30;
```

자체는 일반적인 휴리스틱이다.

하지만 강한 추세에서는 RSI가:

``` text
70 → 72 → 75 → 78
```

처럼 계속 높은 상태를 유지할 수 있다.

따라서:

``` text
RSI > 70 = 고점
```

으로 보면 강한 상승 추세를 너무 일찍 경고할 수 있다.

더 중요한 것은:

``` text
RSI 절대값
+
RSI 방향
+
가격 구조
+
추세 강도
+
모멘텀 변화
```

이다.

예:

``` text
RSI 78
→ 75
→ 69

+ 고점 갱신 실패
+ MACD 둔화
+ 거래량 증가
```

같은 조합이 단순히 `RSI = 72`보다 훨씬 의미 있는 exhaustion 신호가 될 수
있다.

------------------------------------------------------------------------

# 15. Bollinger Upper Band 돌파도 그 자체로 과열은 아님

현재:

``` java
upperBandBreak = currentPrice >= upperBand;
```

를 과열/클라이맥스 판단에 강하게 사용한다면 주의해야 한다.

강한 상승 추세에서는 가격이:

> Upper Band를 따라 계속 움직이는

"Band Walk"가 발생할 수 있다.

따라서:

``` text
Upper Band 돌파
```

만으로 고점 신호로 판단하지 말고:

-   Band Width
-   Band Width 변화
-   RSI
-   MACD
-   고점 구조
-   거래량
-   캔들 확장

등과 함께 판단하는 것이 좋다.

------------------------------------------------------------------------

# 16. 손절 가격도 구조 기반으로 바꾸는 것이 좋음

현재 손절 계산에:

``` java
double minStopDistance =
        Math.max(cur * 0.015, atr * 0.8);
```

같은 고정 비율 + ATR 방식이 사용된다면 한계가 있다.

예를 들어:

``` text
저변동성 종목
고변동성 종목
```

에 동일한 `1.5%` 기준을 적용하는 것은 시장 구조를 충분히 반영하지
못한다.

### 권장

손절은:

``` text
Support Zone Low
-
ATR Buffer
```

또는:

``` text
Swing Low
-
ATR Buffer
```

방식으로 잡는다.

예:

``` java
stopLoss =
    supportZoneLow - atr * 0.3;
```

초기 튜닝에서는 대략 `0.3 ~ 0.5 ATR` 정도의 버퍼를 테스트할 수 있다.

------------------------------------------------------------------------

# 17. RR 1.2 하드 필터는 마지막 단계에서 사용

현재:

``` java
if (riskRewardRatio < 1.2)
    recWeight = 0;
```

같은 방식이라면 주의해야 한다.

RR 자체가 나쁜 지표라기보다,

> Entry / Stop / Target이 제대로 계산되었다는 전제

에서만 의미가 있다.

예를 들어 잘못된 Entry와 Target을 사용하면:

``` text
RR = 2.0
```

도 쉽게 만들 수 있다.

따라서 순서는:

``` text
시장 구조
 ↓
진입 구간
 ↓
구조적 손절
 ↓
구조적 목표
 ↓
RR 확인
```

이어야 한다.

RR은 **진입 품질을 만드는 기준이 아니라 최종 feasibility check**에
가깝다.

------------------------------------------------------------------------

# 18. 추천 진입 계산 방식

전체적으로 다음 순서를 권장한다.

``` text
① 현재 Market Regime
       ↓
② 주요 Support / Resistance Zone 생성
       ↓
③ 현재 가격이 어느 Zone에 있는지 판단
       ↓
④ Entry Type 판단
       ├─ Pullback
       ├─ Breakout
       └─ Reclaim
       ↓
⑤ Entry Zone 계산
       ↓
⑥ Trigger 확인
       ↓
⑦ Stop Loss 계산
       ↓
⑧ Target 계산
       ↓
⑨ Risk / Reward 계산
       ↓
⑩ 최종 Weight 계산
```

# 19. Phase 모델도 "한 가지 축"으로 생각하지 않는 것이 좋음

현재 `ChartPhase`가 모든 것을 표현하려고 하면 충돌이 발생하기 쉽다.

예:

``` text
상승 추세인데
동시에 과열이고
동시에 돌파했고
동시에 신규 진입은 위험
```

이것을 하나의 Phase만으로 표현하기 어렵다.

현재 구조를 크게 바꾸지 않는다면 최소한 개념적으로 다음을 분리해
생각하는 것이 좋다.

### Regime

``` text
UPTREND
DOWNTREND
RANGE
TRANSITION
```

### Event

``` text
BREAKOUT
FAKE_OUT
CAPITULATION
RECLAIM
```

### Entry State

``` text
NO_ENTRY
SETUP
ENTRY_READY
RE_ENTRY
HOLD
AVOID
```

실제 enum을 당장 분리할 필요는 없지만, **판단 로직 자체는 이 세 축을
의식해서 작성하는 것**이 좋다.

# 21. 가장 중요한 개선 포인트

현재 로직의 가장 큰 문제는 개별 지표가 부족한 것이 아니다.

오히려 지표는 충분히 많다.

문제는:

> **지표 → 시장 구조 → 타점으로 변환하는 과정**

이다.

현재는:

``` text
RSI
MACD
ADX
MA
VWAP
POC
Bollinger
Volume
ATR
...
       ↓
조건 점수
       ↓
Phase
       ↓
ATR 기반 가격
```

에 가까운데,

개선 방향은:

``` text
시장 국면
       ↓
추세/횡보 판단
       ↓
핵심 가격대
       ↓
가격의 위치
       ↓
수급/모멘텀 변화
       ↓
진입 패턴
       ↓
진입 구간
       ↓
손절 구조
       ↓
목표 구조
       ↓
RR
       ↓
Position Weight
```

이다.

# 22. 우선순위 TOP 5

## 1순위 --- 캔들 계산 오류 수정

``` java
bodyTop = max(open, close)
bodyBottom = min(open, close)
```

이것부터 수정.

------------------------------------------------------------------------

## 2순위 --- ATR 중심 Entry 계산 제거

ATR은:

-   진입 거리
-   손절 버퍼
-   돌파 과확장 여부

등에 활용하고,

**진입가 자체는 Support/Resistance Zone을 중심으로 계산.**

------------------------------------------------------------------------

## 3순위 --- Pullback / Breakout / Reclaim 분리

`ENTRY_READY` 하나에 모든 진입 상황을 넣지 않는다.

------------------------------------------------------------------------

## 4순위 --- Recovery 조건 강화

하루짜리 반등을 Recovery로 보지 않고:

``` text
반등
→ 재조정
→ Higher Low
→ 주요 레벨 회복
```

순서로 확인.

------------------------------------------------------------------------

## 5순위 --- 지표 중복 집계 감소

다음처럼 독립적인 증거 그룹으로 묶는다.

``` text
Trend
Momentum
Volume
Price Action
Structure
```

같은 현상을 여러 지표가 동시에 측정한다고 해서 동일한 방향의 점수를 계속
더하지 않는다.

------------------------------------------------------------------------

# 23. 유지해도 좋은 현재 로직

현재 구현에서 방향 자체가 좋은 부분도 많다.

### 유지 권장

-   ATR
-   MA20 / MA50 구조
-   POC
-   VWAP
-   최근 고점 / 저점
-   거래량
-   MACD
-   Fake-out 감지
-   Capitulation 감지
-   STRONG_HOLD와 ENTRY_READY 구분
-   2일 이상 MA20 이탈 같은 노이즈 방지 장치

즉, **지표를 갈아엎을 필요는 없다.**

핵심은 기존 지표들을:

> "시장 구조를 설명하는 증거"

로 사용하고, 그 결과를 실제 타점에 연결하는 것이다.

# 25. 다음 작업에서 권장하는 순서

다음 단계에서는 전체 파일을 다시 뜯어고치기보다 아래 두 메서드부터 실제
코드로 개선하는 것이 좋다.

``` text
1. determinePhase()
2. calculateTargets()
```

그리고 그 전에 필요한 보조 계산:

``` text
3. Support Zone 계산
4. Resistance Zone 계산
5. Breakout Distance ATR 계산
6. Pullback / Breakout / Reclaim 판정
7. Structural Stop 계산
```

그 후 마지막으로:

``` text
8. recommendedWeight
```

를 붙인다.

즉:

``` text
Phase
 ↓
Structure
 ↓
Entry Type
 ↓
Entry Zone
 ↓
Stop
 ↓
Target
 ↓
RR
 ↓
Weight
```

순으로 완성하는 것이 가장 자연스럽다.
